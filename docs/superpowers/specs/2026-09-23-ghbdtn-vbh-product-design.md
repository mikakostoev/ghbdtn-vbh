# ghbdtn vbh: из репозитория в продукт

Дата: 2026-09-23. Статус: одобрен в обсуждении, ждёт реализации.

## Цель

LayoutSwitcher становится бесплатным open-source продуктом с лицом: своё имя, гладкий первый запуск, сайт,
готовый пайплайн подписи. Обещание README «в приложении нет сетевого кода» сохраняется дословно. Функции Punto
Switcher (автозамена, транслит, смена регистра, дневник), Windows, монетизация, App Store и автообновления внутри
приложения в эту работу не входят.

Решения, принятые с автором:

- Имя продукта: **«ghbdtn vbh»**, целиком, с пробелом. Слоган: «ghbdtn vbh → привет мир».
- Apple Developer ID пока не покупается: подпись остаётся ad-hoc, пайплайн для настоящей подписи готовится
  заранее и включается секретами.
- Сайт: GitHub Pages из папки `docs/` этого репозитория, без домена.

## 1. Переименование

Имена:

| Где | Было | Станет |
|---|---|---|
| Бандл | `LayoutSwitcher.app` | `ghbdtn vbh.app` |
| Отображаемое имя, `CFBundleName`, `CFBundleDisplayName` | LayoutSwitcher | ghbdtn vbh |
| `CFBundleIdentifier` | `local.layoutswitcher` | `app.ghbdtnvbh` |
| SwiftPM-пакет, таргет, исполняемый файл, `Sources/…` | LayoutSwitcher | `ghbdtnvbh` (без пробела: скрипты и `swift build` не любят пробелы) |
| Иконка в бандле | `LayoutSwitcher.icns` | `ghbdtnvbh.icns` |
| Архив релиза | `LayoutSwitcher-1.1.0.zip` | `ghbdtn-vbh-2.0.0.zip` |
| Cask | `Casks/layoutswitcher.rb`, токен `layoutswitcher` | `Casks/ghbdtn-vbh.rb`, токен `ghbdtn-vbh` |
| Репозиторий | `mikakostoev/layout-switcher` | `mikakostoev/ghbdtn-vbh` |
| Application Support | `~/Library/Application Support/LayoutSwitcher/` | `~/Library/Application Support/ghbdtn vbh/` |

Что меняется в файлах: `Package.swift`, `build.sh`, `release.sh`, `test.sh`, `Tests/live.sh`, три workflow,
cask, `.gitignore`, `README.md`, `CONTRIBUTING.md`, `NOTICE.md`, `Resources/*/Localizable.strings` (ключи с
префиксом «LayoutSwitcher:»), `main.swift` (тултипы, заголовок окна, описание иконки в строке меню),
`Settings.swift` (имя папки). `Tools/icon.swift` не меняется: иконка-клавиша, разделённая на латиницу и
кириллицу, остаётся; словесный логотип живёт только на сайте.

Миграция данных: при старте, если `…/LayoutSwitcher/` есть, а `…/ghbdtn vbh/` нет — папка переименовывается
одним вызовом `FileManager.moveItem`. UserDefaults (включено/выключено, исключённые приложения, триггер Option)
живут в домене bundle ID и сбросятся к значениям по умолчанию; миграция не делается — два релиза, ноль звёзд.
Грант Accessibility слетит по той же причине; окно первого запуска (раздел 2) объясняет это.

Репозиторий переименовывается через `gh repo rename ghbdtn-vbh`; GitHub ставит редирект, старый tap и старые
ссылки продолжают работать. Обновляются описание репо, `origin` в локальном клоне и команда установки:

```bash
brew tap mikakostoev/ghbdtn-vbh https://github.com/mikakostoev/ghbdtn-vbh && brew install --cask --no-quarantine ghbdtn-vbh
```

Версия: следующий тег после всей работы — `v2.0.0`, потому что сменились имя, bundle ID и cask.

## 2. Окно первого запуска

Новый файл `Sources/ghbdtnvbh/Onboarding.swift`, SwiftUI-вью в обычном `NSWindow`, около ста строк.

Когда показывается:

- При запуске, если `startTap()` не удался (нет Accessibility). Системный алерт от
  `AXIsProcessTrustedWithOptions` остаётся: он добавляет приложение в список, где надо поставить галочку.
- Из пункта меню «Нет доступа: Универсальный доступ…» — вместо прямого перехода в настройки открывается это окно.

Содержание:

1. Иконка приложения (`NSApp.applicationIconImage`), имя «ghbdtn vbh», одна фраза: «Чтобы исправлять раскладку,
   приложению нужно видеть, что вы печатаете».
2. Кнопка «Открыть Универсальный доступ» — существующий `openAccessibility()`. Под ней строка состояния:
   «Ждём разрешения…», которая становится «Доступ есть ✓», когда `AXIsProcessTrusted()` вернёт true. Вью
   опрашивает сама, таймером раз в секунду, пока окно открыто; таймер Switcher-а, который поднимает tap, не
   трогаем.
3. После галочки появляется поле «Попробуйте: наберите ghbdtn vbh и нажмите пробел» и кнопка «Готово». Поле —
   обычный `TextField`; собственное окно приложения не исключено из обработки, слово исправится в нём как в любом
   другом.

Два варианта текста, выбираются по флагу `onboarded` в UserDefaults, который ставится при первом успешном
`startTap()`:

- флага нет — «первый запуск», текст выше;
- флаг есть, а tap нет — «после обновления»: «Обновление сменило подпись приложения, и macOS забыла разрешение.
  Снимите галочку у ghbdtn vbh и поставьте снова». Это закрывает главную боль ad-hoc подписи; когда появится
  Developer ID, этот вариант просто перестанет показываться.

Строки локализуются в `Resources/{en,ru}.lproj/Localizable.strings`, как остальные.

Меню получает два пункта:

- «О программе ghbdtn vbh» — `NSApp.orderFrontStandardAboutPanel`, версия берётся из `Info.plist`; в `build.sh`
  добавляется `CFBundleVersion`, иначе панель покажет пустую строку сборки.
- «Проверить обновления…» — `NSWorkspace.shared.open` на `https://github.com/mikakostoev/ghbdtn-vbh/releases`.
  Это открытие ссылки в браузере, а не сетевой код; `grep` из README по-прежнему пуст.

## 3. Сайт

GitHub Pages раздаёт папку `docs/` с ветки `main`. Никаких генераторов, сборщиков, внешних скриптов и шрифтов.

Файлы:

- `docs/index.html` — английская страница; `docs/ru/index.html` — русская; в шапке ссылка друг на друга.
- `docs/.nojekyll` — чтобы Pages отдавал файлы как есть и не пытался собирать этот спек как Jekyll-страницу.
  Спеки под `docs/superpowers/` при этом тоже доступны по URL; для открытого репозитория это приемлемо.
- `docs/demo.gif` — `.github/demo.gif` переезжает сюда (Pages не видит `.github/`), README и `Tools/demo.sh`
  указывают на новый путь. Бинарник в репозитории остаётся один, как требует CONTRIBUTING.
- Иконка на сайте — не PNG, а inline-SVG, повторяющий рисунок `Tools/icon.swift` (скруглённый квадрат, диагональ,
  две буквы). Ещё один бинарник не добавляется.

Содержание страницы сверху вниз:

1. Шапка: словесный логотип «ghbdtn vbh», под ним эффект набора: печатается `ghbdtn vbh`, пробел, текст
   превращается в «привет мир». Двадцать строк JS без библиотек; без JS показывается конечная строка.
2. demo.gif.
3. Установка: команда Homebrew и ссылка на zip последнего релиза (`…/releases/latest`), короткая
   подсказка словами про «Open Anyway» и Accessibility, без скриншота.
4. «Почему можно доверять» — блок из README без изменений смысла: нет сети, короткий открытый код, ничего не
   хранится, пароли не читаются, три текстовых файла.
5. Языки — краткая версия раздела README: где работает как русский и английский, где хуже, где нет.
6. Подвал: GitHub, Releases, лицензия MIT, NOTICE.

Оформление: системный шрифт, светлая и тёмная тема через `prefers-color-scheme`, одна колонка до 720 px, читается
с телефона. Цвета берутся из `Tools/icon.swift` (акцент `#2869E5`, чернила `#1B1D21`).

После первого деплоя: `gh repo edit --homepage <url>`, ссылка на сайт в первой строке README.

## 4. Пайплайн подписи, выключенный до появления сертификата

`release.yml` получает шаги, которые выполняются, только если заданы секреты (проверка через `env`, потому что
`secrets` нельзя читать в `if` напрямую):

| Секрет | Что это |
|---|---|
| `DEVELOPER_ID_P12` | сертификат «Developer ID Application» с ключом, base64 от `.p12` |
| `DEVELOPER_ID_P12_PASSWORD` | пароль к `.p12` |
| `NOTARY_APPLE_ID`, `NOTARY_TEAM_ID`, `NOTARY_PASSWORD` | Apple ID, Team ID и app-specific password для `notarytool` |

Шаги при наличии секретов: импорт `.p12` во временный keychain; `release.sh` вызывается с
`IDENTITY="Developer ID Application: …"`; `xcrun notarytool submit … --wait`; `xcrun stapler staple` на `.app`;
архив пересобирается уже со степлером. Без секретов — ad-hoc, как сейчас.

Правки в скриптах: `release.sh` перестаёт жёстко ставить `IDENTITY=-` и берёт `${IDENTITY:--}`; `build.sh`
добавляет `--options runtime --timestamp` к `codesign`, когда identity не ad-hoc (hardened runtime нужен для
нотаризации; event tap и Accessibility с ним совместимы без entitlements). Список секретов и порядок действий
описываются комментарием в начале `release.yml` и абзацем в CONTRIBUTING.

Кода приложения этот раздел не касается.

## 5. Проверка

- `./test.sh` и `test.yml` зелёные с новыми путями; `--selftest` без изменений.
- Окно первого запуска, живьём: `tccutil reset Accessibility app.ghbdtnvbh`, запуск, оба варианта текста
  (первый запуск и «после обновления», второй — выставив флаг `onboarded` руками), выдача доступа, слово
  исправляется в тестовом поле.
- `Tests/live.sh` — раз затронут `main.swift`.
- Сайт: открыть `docs/index.html` и `docs/ru/index.html` локально, в широком и узком окне, в светлой и тёмной теме;
  проверить, что без JS страница читается.
- Пайплайн подписи: без секретов релиз проходит как раньше (проверяется тегом-кандидатом или `workflow_dispatch`);
  ветка с секретами проверяется, когда появится сертификат.

## Порядок работ

Четыре независимых PR, в этом порядке, каждый оставляет `./test.sh` зелёным:

1. Переименование (раздел 1), включая переименование репозитория.
2. Окно первого запуска и пункты меню (раздел 2).
3. Сайт и включение Pages (раздел 3).
4. Пайплайн подписи (раздел 4).

После четвёртого — тег `v2.0.0`.
